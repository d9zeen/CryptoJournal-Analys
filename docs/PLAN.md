## Продукт

Онлайн-дневник сделок для русскоязычных криптотрейдеров (фьючерсы Bybit, BingX, OKX + спот).
Модель — подписка Free / Pro. В MVP оплаты нет: только поле `plan` у пользователя и проверка лимитов.

## Формулы

Обозначения: `size` — размер позиции в USD (номинал), `dir` = +1 для long, −1 для short.

- **Linear (USDT/USDC-фьючерсы) и спот:** `qty = size / entry`, `gross = dir × (exit − entry) × qty`
- **Inverse (coin-margined, BTCUSD):** `gross_coin = dir × size × (1/entry − 1/exit)`, `gross = gross_coin × exit` (в USD по цене выхода)
- **Спот:** только long, плечо 1
- **PnL** = `gross − fee + funding` (fee — сумма комиссий в USD, funding со знаком)
- **Плечо на PnL в $ не влияет** — только на маржу и ROE%
- **Риск $** = `size × |stop − entry| / entry` (одинаково для linear и inverse)
- **R-multiple** = `PnL / риск`. Без стопа R не считается и не входит в средний R
- **Winrate** = прибыльные / закрытые
- **Profit factor** = Σ прибылей / |Σ убытков|
- **Макс. просадка** = наибольшее падение от пика кривой накопленного PnL (в $; в % — если задан стартовый депозит)
- **Топ ошибок** = сумма убытков сделок с этим тегом (сделка с двумя тегами учитывается в обоих)
- Статистика по часам и дням недели — в часовом поясе пользователя (хранение в UTC)
- Фильтр периода в списке сделок — по дате входа; неделя начинается с понедельника

PnL считается автоматически, но его можно поправить вручную (флаг `pnl_manual`).

### Дашборд (этап 3, `src/lib/calc/stats.ts`)

- Период дашборда фильтрует сделки **по дате входа** (как список сделок). По умолчанию — «Всё время»
- В статистику — только закрытые сделки с PnL; открытые показываются отдельной строкой-счётчиком
- **Матожидание** = суммарный PnL / число закрытых сделок
- **Безубыточная сделка** (PnL = 0) — не прибыльная и не убыточная, но входит в знаменатель винрейта
- **Profit factor** без убытков = ∞
- **Просадка:** пик кривой считается с нуля (до первой сделки), поэтому убыток с первой сделки — тоже просадка.
  В %: (пик − текущее) / (стартовый депозит + пик)
- **Кривая PnL** и **PnL по дням** — по времени выхода; **дни недели и часы** — по времени входа.
  Всё в часовом поясе из профиля (если пусто — пояс браузера)
- Таблицы: Long/Short, сетапы, топ ошибок, эмоции, пары

### Импорт CSV (этап 4, `src/lib/import/`)

**Обновление (ноябрь 2026): импорт с любой биржи.** Один движок (`universal.ts`) для Bybit, Binance, OKX, BingX, Bitget, MEXC и «Другой»:
- вид выгрузки определяется по колонкам: есть цены входа/выхода → **закрытые позиции** (`positions.ts`);
  есть цена исполнения → **история исполнений** (`fills.ts`), из которой сделки собираются сами:
  по каждой паре по времени — открытие с нуля, доливки усредняют вход, встречные исполнения закрывают,
  разворот делит исполнение (и комиссию) на две сделки; не закрытые к концу файла позиции не импортируются;
  спот — только long, продажа без покупки в файле пропускается
- Buy/Sell в выгрузке позиций: у Bybit Closed P&L — закрывающий ордер, у остальных — направление позиции;
  заголовок колонки («Closing…», «Position…») важнее настройки биржи
- PnL из файла: если он ближе к валовому PnL, чем к PnL после комиссий (Binance «Realized Profit»), вычитаем комиссии сами
- комиссия в $: валюта-доллар — как есть, базовая монета пары — × цена, посторонняя (BNB) — не учитываем + предупреждение
- файлы: CSV и Excel `.xlsx` (свой читатель на `fflate`, первый лист, заголовок отчёта над таблицей пропускается)
- рынок: «по паре» (BTCUSD / *-USD-SWAP — coin-M, остальное — USDT) или вручную (в т.ч. спот)
- id сделки из истории исполнений: отпечаток (пара, сторона, время открытия, id первого исполнения)

- Цепочка: `csv.ts` (разбор файла) → `mapping.ts` (колонки по синонимам, EN + RU) → парсер биржи (`bybit.ts`) → `plan.ts` (новые / дубли / ошибки / сверх лимита)
- **Bybit Closed P&L:** сторона в файле — это закрывающий ордер: **Sell → long, Buy → short**
- Размер позиции: «Стоимость входа», иначе `объём × цена входа`. Инверсные (BTCUSD): объём = $, PnL и комиссии в монете → × цену выхода
- **PnL берём из файла** (биржевой). Если он расходится с формулой больше чем на max(0,01 $; 0,05 % размера) — `pnl_manual = true`
- Комиссии — открытие + закрытие (по модулю). Если колонок с комиссиями нет — комиссия = валовый PnL − PnL из файла
- Времени входа в Closed P&L нет — ставим время выхода (предупреждение в предпросмотре)
- Часовой пояс времени — из заголовка вида `Trade Time(UTC+0)`, иначе UTC; можно выбрать руками
- **Дубли:** `external_id` = `o:<Order ID>`, без него — `h:<отпечаток строки>`; одинаковые строки файла → `#2`, `#3`.
  Уникальность `(user_id, exchange, external_id)` в БД. Существующие id проверяем ДО вставки: триггер лимита срабатывает
  до проверки уникальности, но ошибка откатывает и счётчик — дубль лимит не тратит (проверено в `rls_test.sql`)
- **Лимит Free:** если всё не влезает — импортируем самые старые сделки (по выходу), остальные помечаем «сверх лимита»
- Вставка пачками по 100; журнал `imports` хранит сколько строк было / импортировано / пропущено
- **Отмена импорта** удаляет его сделки и запись журнала. Лимит не возвращается (как и при обычном удалении)
- Новая биржа = новый файл парсера + строка в `registry.ts`

## Схема БД (этап 2, `supabase/migrations/0001_init.sql`)

Количество монет не храним — считается как `size_usd / entry_price`. Для PnL в USD формулы linear и inverse дают одинаковый результат (разница только в валюте залога).

- `profiles` — id (= auth.users.id), display_name, plan (free/pro), plan_until, timezone, starting_balance, locale, created_at
- `trades` — id, user_id, exchange, market_type (linear/inverse/spot), symbol, side, entry_at, exit_at (NULL = открыта), entry_price, exit_price, size_usd, leverage, fee, funding, stop_loss, take_profit, pnl, pnl_manual, r_multiple, setup_id, emotion_id, note, screenshot_path, source (manual/import), import_id, external_id, created_at, updated_at
- `setups`, `mistake_tags`, `emotions` — личные списки пользователя (с готовыми значениями при регистрации)
- `trade_mistakes` — связь сделка ↔ теги ошибок (многие-ко-многим)
- `trade_screenshots` — скриншоты сделки (до 10), путь `{user_id}/{trade_id}/{uuid}.webp` (миграция 0003; `trades.screenshot_path` больше не используется)
- `imports` — журнал импортов
- `usage_counters` — (user_id, month, trades_created) для лимита Free
- Storage bucket `screenshots` (приватный), путь `{user_id}/{trade_id}.webp`

Безопасность: RLS на всех таблицах и в Storage; `plan` пользователь менять не может; лимит Free проверяется триггером в базе.

## Доступность из РФ (важно)

Cloudflare и Supabase (который тоже за Cloudflare) периодически замедляются российскими провайдерами.
План:
- Порядок (решение от ноября 2026): **сначала всё делаем и проверяем на localhost**, потом выкладываем на GitHub/хостинг, потом подключаем домен.
- Перед запуском (этап 5) — проверить доступность из РФ. Если плохо: свой домен + недорогой VPS вне РФ,
  который отдаёт статику и проксирует запросы к Supabase (~$3–5/мес). Код к этому готов:
  адрес Supabase берётся из переменной окружения, сайт — чистая статика.

## Перед публичным запуском

- Подключить свой SMTP в Supabase (Resend / Brevo, бесплатные тарифы) — встроенная почта Supabase не шлёт письма обычным пользователям.
- Включить подтверждение email.
- Экспорт сделок в CSV (на бесплатном Supabase нет автобэкапов).
